# 06 — UX AUDIT

Status: Phase 4 not started. Below are **preliminary, evidence-backed pressure points** collected while building the product model (Phase 1–2). Each cites where in the code the behaviour lives. Nothing here has been redesigned; all are to be confirmed screen by screen in Phase 4 and prioritised then.

| # | Pressure point | Evidence | Who feels it | Prelim prio |
|---|---|---|---|---|
| U1 | **Two filter systems for one list.** The customer book has rank/category/CRM/status/ageing/balance/source; Reports has CRM/settlement/category chips/ageing bucket chips/search. Same rows, different names for the same concepts ("Overdue (2)" chip vs "Status: Overdue" dropdown), different bulk bars. | `CustomerDashboardView` filters vs `ReportsView` chips | Manager, Admin | P2 |
| U2 | **"Status" means two things.** The book's Status dropdown reads the *stored* status (`item.status`), the Today cards and Reports chips read the *derived* category; after midnight they can disagree until something rewrites the row. | D2 in 03 §9 | everyone | P2 |
| U3 | **Company Today cards navigate away.** On the company dashboard a card press jumps to Reports (`setAdminTab('reports')`) with the filter applied; on the personal dashboard it filters the list in place. Same control, two behaviours. | `renderAdminOverviewCards` vs `renderUserDashboard` | Manager/Admin | P2 |
| U4 | **Destructive actions guarded only by `window.confirm`**: delete customer (cascades cheques + thread), "COMPLETE FRESH START", bulk follow-up date, master import. No undo, no summary of what will be lost beyond the dialog text. | `handleDeleteCustomer`, `handleResetAllDataAndUsers`, `ReportsView` bulk bar | Admin/Manager | P1 |
| U5 | **Stale data with no signal.** A tab open since morning shows the book as it was; another person's edits appear only after a reload; a conflicting save silently wins (R1). Nothing on screen says "last refreshed at …" for the book (the stock tab does). | `useSupabaseSync`, no realtime | everyone | P1 |
| U6 | **Two "expected payment" fields**: the follow-up form's "Expected amount/date" (forecast) and the activity panel's "Promised to pay" (promise). The dashboard's "Promised today" tile counts the first; the email lists both under different headings. | D4 | CRM, Manager | P2 |
| U7 | **Save stamps a follow-up even when nothing about the follow-up changed** (`lastFollowUpOn = now` on every Save) — editing a phone number makes the account look "attended". | `FollowUpModal.handleSave` | Manager (reads the CRM table) | P3 |
| U8 | **The "notes" column and the activity thread drift.** Deleting an activity entry leaves its mirrored line in `notes[]`, which is what the Today list, Reports "Last note" and the email show. | D3 | everyone | P2 |
| U9 | **Legacy vocabulary leaks into the UI**: "Pending" (means no date), "Customer Ledger", "Sheet Synced", "Dr (Due)/Cr (Advance)", "Portfolio", "Instant Report of >90d", "Timely Follow-up Score" vs "Timely Score". | book/Reports copy | new users | P3 |
| U10 | **Seven dialog components, each with its own chrome** (FollowUpModal, CustomerEditModal, PdcModal, UserModal, TemplateModal, WhatsAppReminderModal, ChangePasswordModal, AiReportModal) and no shared Dialog primitive; the stock drawer and compare panel use yet another. | `components/*Modal.tsx`, `Primitives.tsx` has no Modal | everyone | P3 (design system) |
| U11 | **No onboarding or empty-state guidance for a new CRM** whose code matches nothing: the personal Today shows zeros and "Nothing here" with no explanation that accounts must carry their CRM code. | `renderUserDashboard` empty state; seen with the throwaway CRM login | new users, Admin | P2 |
| U12 | **Reports keeps stock-Tailwind colour classes** (`bg-gray-100`, `text-blue-700`…) remapped through the theme, so its chips, tables and cards look like a different product from the book and Today. | `ReportsView.tsx`, `styles/theme.css` "Palette remap" | Manager | P2 (consistency pass) |
| U13 | **Company Today for whole-book users never shows an account list**; every card is a jump to Reports. A Manager on a phone gets four numbers and a portfolio bar, then must change tab. | `renderAdminOverviewCards` | Manager on phone | P3 |
| U14 | **The Data source tab mixes an everyday action (sync) with a catastrophic one (reset) and a one-time one (master import)** on one screen. | `renderCompanyDashboard` source tab | Admin/Manager | P2 |
| U15 | **CRM code as the join key is invisible to users** but decides everything: a login whose code does not match the sheet sees nothing; the app resolves display-name spellings quietly (`findOwner`) but never tells an Admin the code is wrong. | `types.ts findOwner`, DEPLOYMENT.md | Admin | P2 |
| U16 | **Cr (advance) accounts show as "with dues"** in the book, CRM totals and the Receivables tile while having nothing overdue (rule 20 in 03 §6). | `hasOutstanding` | Manager | P3 / business |
